# ADR-001: Greenfield NYC application
Status: selected development baseline; not deployed.

## Decision
Next.js/TypeScript for UI and Node server routes; Supabase for Postgres, Auth and private Storage; Vercel for web deployment.

Why: one language across UI, validation and orchestration; relational constraints/transactions suit parties, contract revisions, signatures and audit history; consolidated auth/storage reduces account setup.
Firebase is viable but gives no inherited advantage for a new application. A bespoke auth/database/storage platform would add operational work before submission.

## Boundaries
Browser -> authenticated application routes -> validated domain services -> Postgres/Storage and server-only Meta adapters.
Client uses Supabase publishable key with RLS. Privileged secret key is restricted to server administration/worker paths; verify actor access explicitly.
Contract files and source photos live in private buckets with bounded access URLs.
Versioned SQL migrations live in this repository. Schema changes are reviewed, not generated by an agent at runtime.

## Proposed modules
app/; src/domain/gigs/; src/domain/contracts/; src/server/providers/; src/server/jobs/; src/server/rendering/; supabase/migrations/; tests/fixtures/.
Tables: gigs, gig_revisions, parties, contracts, signature_invites, signatures, audit_events, assets, jobs, provider_runs.
Owner/participant authorization is explicit; enforce unique signature per party/revision and unique job idempotency keys.

## Jobs
Record input revision before external work, claim with a lease, then persist success/failure. Poll status from UI. Bound retries and reserve budget before requests.
First integration must benchmark image/SAM/PDF latency against actual hosting limits.
For long work select a durable runner (candidate: Inngest) with independent triggers, lease recovery and idempotency. A DB row by itself is not a worker; no live background feature is released until the runner/recovery path passes.
Do not request additional runner credentials until this gate establishes need.

## Providers and rendering
Meta text/image/SAM adapters; exact IDs and API protocol confirmed against current docs and account.
Baseten only for validated P1 need. No OpenAI/Gemini key is required by this baseline.
PDFKit candidate for contract PDF; SVG/Satori + resvg/sharp candidate for poster composition. Test fonts and native dependencies on deployment.
English contract template plus clause-aligned Korean reference. Legal rules remain separately versioned and primary-source verified.
